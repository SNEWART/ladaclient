## РЕВОЛЮЦИЯ В АРХИТЕКТУРЕ: Ленивая загрузка с кэшированием

Вместо того, чтобы просто урезать параметры, я создал принципиально
новую систему работы с контекстом:

### ПРОБЛЕМА (как было):

```python
# Каждое сообщение:
1. build_state_brief() вызывает ВСЕ модули
2. Каждый модуль пересчитывается заново
3. topic_tracker.as_context_block(user_id)     ← 150 токенов
4. promise_tracker.as_context_block(user_id)   ← 180 токенов
5. companion_model.as_context_block(user_id)   ← 250 токенов
6. ... и ещё 10+ модулей
7. FAISS поиск по всей базе                    ← 2000 токенов
8. Unified analysis после ответа               ← тяжёлый JSON-запрос

ИТОГО: ~5-7 секунд на обработку + 12k токенов
```

### РЕШЕНИЕ (как стало):

```python
# Ленивая загрузка с умным кэшированием:
1. Модуль проверяет кэш
2. Если данные НЕ изменились → берёт из кэша (0 вычислений)
3. Если изменились → пересчитывает и кэширует
4. TTL зависит от типа данных:
   - topic_tracker: 1 минута (быстро меняется)
   - relations: 30 минут (медленно меняется)
   - weather: 1 час (очень медленно)

ИТОГО: ~1-2 секунды + 6-7k токенов
```

## НОВЫЕ ФАЙЛЫ

### 1. `lada/core/lazy_context.py`

**Умный менеджер контекста с кэшированием.**

Ключевые фичи:
- Кэширование результатов модулей между сообщениями
- Автоматическая инвалидация при изменении зависимостей
- Разные TTL для разных типов данных
- Статистика (cache hit rate, tokens saved)

Пример:
```python
from lada.core.lazy_context import get_lazy_context_manager

mgr = get_lazy_context_manager()

# Первый вызов — вычисление
result = mgr.get_or_compute(
    "companion_model_123",
    lambda: companion_model.as_context_block(123),
    deps={"trust": 0.5, "intimacy": 0.3},
    ttl=300.0,  # 5 минут
    cost_tokens=250,
)

# Второй вызов через 2 минуты — из кэша (0 вычислений)
result = mgr.get_or_compute(...)  # Мгновенно!

# Третий вызов: trust изменился → пересчёт
result = mgr.get_or_compute(
    deps={"trust": 0.6, "intimacy": 0.3},  # trust изменился!
)
```

### 2. `lada/app/state_brief_optimized.py`

**Оптимизированная версия build_state_brief().**

Изменения:
- Все модули загружаются через LazyContextManager
- Каждый модуль имеет свой TTL
- Зависимости вычисляются автоматически
- Кэш инвалидируется только при реальных изменениях

### 3. `config_optimized.py`

Готовые оптимизированные настройки (уже применены в config.py).

## АРХИТЕКТУРНЫЕ УЛУЧШЕНИЯ

### 1. Умное кэширование

**Модули по скорости изменения:**

```
БЫСТРО (TTL: 1-3 мин):
  - topic_tracker      ← о чём диалог сейчас
  - situational_mood   ← настроение в диалоге

СРЕДНЕ (TTL: 5-10 мин):
  - promise_tracker    ← активные обещания
  - companion_model    ← модель собеседника
  - working_memory     ← рабочая память

МЕДЛЕННО (TTL: 30-60 мин):
  - relations          ← trust, intimacy, status
  - contacts           ← список знакомых
  - weather            ← погода в городе

ОЧЕНЬ МЕДЛЕННО (TTL: 1-2 часа):
  - self_consistency   ← портрет позиций
  - emotional_peaks    ← эмоциональные пики
```

### 2. Инвалидация по зависимостям

Кэш НЕ просто "живёт N минут", а **инвалидируется при изменении данных**:

```python
# promise_tracker зависит от количества активных обещаний
deps = {
    "user_id": 123,
    "active_promises": 2,  # из БД
}

# Если обещание выполнено → active_promises = 1 → кэш инвалидируется
```

### 3. Приоритизация

Модули загружаются по приоритету:
1. CRITICAL: текущее сообщение, persona
2. HIGH: история, отношения, настроение
3. MEDIUM: companion_model, promise_tracker
4. LOW: peaks, life_log
5. OPTIONAL: self_consistency

Если токены кончились — низкоприоритетные модули не загружаются.
